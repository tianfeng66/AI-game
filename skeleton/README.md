# 火柴人领地 — 河谷之境（3D 地图版）

> 更新历史见 [CHANGELOG.md](CHANGELOG.md)。

**从旧版更新：先停止旧服务，再运行 `npm install` 和 `npm start`，浏览器按 Ctrl+F5 刷新。**

> 按 agent-blueprint「先方案后代码」产出。本骨架是**可运行的最小闭环**，不是完整产品。
> 配套方案见 `../方案.md`，需求见 `../PRD.md`。
> **技术栈：Three.js / WebGL + JavaScript + Node.js + WebSocket**。

## 一键运行

```sh
cd skeleton
npm install        # 安装依赖（只需一次）
npm start          # 启动服务端
```

然后浏览器打开 `http://localhost:8080`。**开两个标签页（或两台电脑访问同一地址）即可 2 人对战**。

若 8080 已被别的程序占用（终端会打印 `端口 8080 已被其他程序占用`），换端口即可，网页客户端自动跟随：

```sh
PORT=8081 npm start          # Git Bash；CMD 用 set PORT=8081 && npm start
```

然后打开 `http://localhost:8081`。可用 `curl http://localhost:8081/health` 确认是游戏服务（应返回含 `"game":"stickman-territory"` 的 JSON）。

- 本机测试：开两个浏览器标签页分别进 `http://localhost:8080`。
- 局域网联机：把 `localhost` 换成主机 IP，其他人访问 `http://主机IP:8080`。
- 全部回归：`npm run test:all`（依次运行九组测试，任一失败即停止）。
- 自测逻辑：`npm test`（模拟对局，验证采集/生产/化身/升级/建造/投降/胜负）。
- 联机回归：`npm run test:network`（独立使用 18081 端口，验证本地 3D 模块、双客户端化身/退出及重新开局，结束自动关闭）。

## 操作

| 按键 | 作用 |
|---|---|
| WASD / 方向键 | 化身时移动 |
| Space | 化身时攻击 |
| 鼠标单击己方单位 | 俯视接管，再点击地面移动，点击敌人攻击 |
| 鼠标单击己方箭塔 | 显示攻击范围，可升级（消耗递增的金币与木材），Esc /「关闭」退出 |
| 鼠标单击己方基地 | 查看信息并升级（消耗递增的金币与矿石），Esc /「关闭」退出 |
| 鼠标单击资源点 | 查看归属与信息；己方占领后可升级（需基地等级领先），Esc /「关闭」退出 |
| 鼠标双击己方单位 | 化身该单位 |
| X | 解除选中单位的接管与指令，恢复自动行动 |
| 左键拖动 | 框选己方部队，Shift 可追加选择 |
| A | 进入攻击目标选择，再点击敌人 |
| H | 选中部队回家，到达后恢复原职位 |
| P | 轮换化身下一个己方单位 |
| Esc | 退出化身，返回俯视，单位恢复自动行动 |
| 右键拖动 | 俯视时平移地图；化身时转动镜头 |
| 滚轮 | 俯视时缩放地图；化身时调整跟随距离 |
| U | 阵营升级（金币+矿产，全阵营 +攻 +血） |
| B | 打开箭塔选址，单击锁定、双击建造；再次按 B 或 Esc 取消选址 |
| O | 投降（出局） |
| L | 加入其它阵营（并入对方共享胜负） |

## 已实现（最小闭环）

- 网页联机（Node.js 权威服务器 + WebSocket，20 tick/秒）
- 每局 2~10 人（服务端硬上限），不足自动补 AI 阵营；出生点按占位索引分配，满员明确拒绝
- 掉线 60 秒宽限 + 自动重连恢复原阵营，期间单位继续 AI 自治
- 基地生产三种兵种（工人/战士/射手，上限 8）
- AI 自治按兵种区分：工人采集+逃跑、战士追击、射手风筝
- 四类资源采集 + 上缴；AI 会「缺什么采什么」补缺口
- 经济回路：生产耗金币+粮食、食物维持（0.2/单位/秒）、断粮饥饿掉血
- 化身切换 + 化身 BUFF（攻击 +20%、生命 +20%、移速 +15%，仅化身期）
- 抢占基地、建造与升级箭塔、升级基地、升级资源点、阵营升级、投降、加入阵营
- 胜负判定：只剩一个阵营 / 时间到积分最高（默认 10 分钟）
- 摄像机跟随化身单位 / 全局俯瞰

## 默认假设（改 `server/game.js` 顶部 `Config`）

| 项 | 默认值 |
|---|---|
| 单局 | 600 秒 |
| AI 思考 / 采集 | 0.2 秒决策一次（`Config.aiThinkInterval`，浮点容差 1e-8）；采集按真实决策间隔累积小数余量，不再每步向上取整 |
| 起始资源 | 金 30 / 粮 50 / 木 30 / 矿 20 |
| 生产 | 每角色耗 10 金 + 5 粮，8 秒一个，上限 8 |
| 食物维持 | 0.2/单位/秒；断粮每秒掉血 5 |
| 升级 | U：第 N 级耗 50×N 金 + 20 矿，每级 +15% 攻血（最高 5 级） |
| 箭塔 | B：耗 30 木 + 15 金，攻 15 / 射程 6 / 血 200 |
| 箭塔升级 | 点击己方箭塔显示攻击范围并可升级；升到 Lv.N+1 耗 10×N 金 + 20×N 木，每级 +25% 攻 / +25% 血 / +0.5 射程（最高 5 级） |
| 基地升级 | 点击己方基地升级；升到 Lv.N+1 耗 30×N 金 + 15×N 矿，每级 +25% 生命 / 出兵提速 12%（最高 5 级） |
| 资源升级 | 点击己方占领的资源点升级；升到 Lv.N+1 耗 8×N 金 + 10×N 木，每级 +25% 采集量与储量（最高 5 级，需基地等级领先） |
| 资源占领 | 工人首次采集某资源点即占领（显示阵营色圈），占领后方可升级；所有阵营仍可采集 |
| 施工 | 工人到场后 12 秒，施工距离 1.8；完工前不能攻击 |
| 自然恢复 | 人物每 10 秒恢复最大生命的 1%，建筑除外 |
| 积分 | 击杀 10 / 击杀被化身 30 / 占基地 100 / 拆塔 15 / 资源 1/100 折算 |
| 击杀奖励 | 每击杀 1 名敌方单位 +2 金币（`Config.killRewardGold`） |

**兵种表（`Config.unitStats`）**：

| 兵种 | 生命 | 攻击 | 移速 | 携带 | 采集 | 射程 | 视野 | 攻击间隔 |
|---|---|---|---|---|---|---|---|---|
| 工人 | 80 | 5 | 4.0 | 25 | 6/s | 1.5 | 8 | 0.8s |
| 战士 | 150 | 18 | 5.0 | 5 | 2/s | 1.5 | 10 | 0.8s |
| 射手 | 70 | 12 | 4.5 | 8 | 2/s | 18.0 | 22 | 1.2s |

## 当前待做（按优先级）

1. **浏览器 GPU 视觉验收**：九组测试均为 CPU/VM 模拟，历次迭代都未做真机画面验收，这是上线前最大风险。
2. **平衡校准**：采集速率校准后经济更紧，战士 AI 偏凶，60 秒内可能打崩一方；需调进攻阈值、起始资源或出生点距离。（2026-11-17：无单位阵营的死锁已修复；10 人局仍偏凋零，300 秒时场上约 17 单位，需重新调食物维持、兵种成本和战士进攻阈值。）
3. **PRD 缺口**：「占领资源点 +2 分/秒」尚未实现（当前积分只有击杀、占基地、拆塔、结余折算）。
4. **途中避障寻路**：终点校验已做，实际移动仍是直线，会穿过树木和建筑；需基础碰撞 + 网格寻路。前置：24 个采集点中有 4 个在矿洞占地内，需先挪开，否则寻路后不可达。
5. **加入阵营的产品语义**：目前并入方共享胜负但不再直接指挥，等级不换算；如需共享控制权或等级继承需单独设计。
6. **网络体验**：状态包仍是全量（已瘦身至 16 KB/帧），无客户端预测/外推、无增量同步与视野裁剪，公网延迟下化身手感会偏钝。
7. **选阵营 UI**：L 键仍自动选第一个可加入的其它阵营；小地图与建造面板已完成。
8. **满员后的产品行为**：目前满员直接拒绝，尚无观战或下一局排队。

## 注意

- 这是**骨架**，跑通后按 `../迭代记录.md` 流程用 `revise` 加需求，不要一次堆满。
